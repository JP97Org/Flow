# AGENTS.md

## Project shape

- Java 21 / Quarkus 3.36 backend plus an Angular 22 frontend in `frontend/`. The frontend is not a Maven module; it is built separately or via the `with-frontend` profile.
- `src/main/java/org/jojo/flow/Main.java` is only a placeholder; Quarkus boots the app.
- REST API lives under `/api/flow` in `rest/ModelFacadeResource`. `rest/ModelFacadeService` holds application-scoped REST state; DTOs and domain-to-DTO mapping are in `rest/dto` and `rest/FlowChartMapper`.
- Backend packages: `model/api` (interfaces and facades), `model/data`, `model/flowChart`, `model/simulation`, `model/storeLoad` (XML DOM), `model/util`.
- `docOriginalFlow/` contains design/report PDFs for the original C++ project; treat them as domain reference, not implementation guidance.
- Optional module jars are loaded from the comma-separated `flow.modules.jars` config property; `MockModule` is always available as a built-in.

## Commands

Backend:
- Package without tests: `mvn -B -DskipTests package` (produces `target/flow.jar` and `target/openapi/openapi.json`).
- Run tests: `mvn -B test`.
- Run one test: `mvn -B -Dtest=org.jojo.flow.test.model.data.MathMatrixTest test`.
- Run backend dev server: `./docker-dev.sh` (mounts the repo, uses JDK 21 Maven image, port 8080; enables CORS for `localhost:4200`). It does not start the frontend.

Frontend:
- Install: `cd frontend && npm ci`.
- Dev server: `npm start` (serves on `http://localhost:4200` and proxies `/api` and `/q` to `http://localhost:8080`). Start the backend first.
- Tests: `npm test` (Vitest via Angular's unit-test builder, jsdom/Node by default). Use `--watch=false` for one-shot and `--include=...` or `--filter=...` to narrow.
- Build: `npm run build` (outputs `frontend/dist/frontend/browser`).
- Formatting follows `frontend/.prettierrc` (single quotes, 100-column width); there is no lint script.

Full builds:
- `./docker-build.sh` runs the complete multi-stage build and tags the image `flow-build`.
- `mvn -B -Pwith-frontend -DskipTests package` runs `npm ci`, regenerates the API client, builds Angular, and copies it into `META-INF/resources`. It expects `target/openapi/openapi.json` to already exist, so run the backend package first (or use `docker-build.sh`).

## Generated frontend API client

- `frontend/src/app/api` is generated by OpenAPI Generator from the backend schema and is committed; do not hand-edit it.
- After REST routes, DTOs, or OpenAPI annotations change: run `mvn -B -DskipTests package`, then `cd frontend && npm run generate:api`, and commit the regenerated files.
- Quarkus derives OpenAPI operation IDs from resource method names (`operation-id-strategy=METHOD`), so renaming a resource method changes the generated client API.
- `app.config.ts` calls `provideApi('')`; the dev proxy supplies same-origin `/api` URLs.

## Test caveats

- Tests use JUnit Jupiter (`org.junit.jupiter.api`), not JUnit 4; the Quarkus BOM supplies the version. Place new tests under the mirrored `org.jojo.flow.test.*` package.
- Full `mvn test` currently has two pre-existing failures; do not assume your change caused them:
  - `IntegrationTest.simpleTests` hardcodes `/home/jojo/...` paths for external jars and XML output, so it fails outside that machine.
  - `FactoryUtilTest.mapTest` is order-dependent: it passes alone but fails in the full suite because the factory is already initialized by earlier tests.
- `FactoryUtil`, `ModelFacade`, its main flowchart, and its ID counter are global/static state that persists across tests. Focused tests are more reliable than assuming test isolation.

## Architecture conventions

- `model/api` interfaces provide static `getDefaultImplementation()` methods. `model/util/DefaultFactory.initialize()` maps every API interface to its implementation; register new API implementations there or the getter returns `null` and reports a warning.
- `ModelFacade` owns flowchart ID allocation and the main flowchart. REST state lives in the application-scoped `ModelFacadeService`; `POST /api/flow/main` replaces the main flowchart.
- Domain objects follow an interface + default implementation pattern, with exceptions under `flow/exc` and warnings collected via `Warning`.
- Keep the REST boundary on DTOs; do not expose model interfaces directly.
